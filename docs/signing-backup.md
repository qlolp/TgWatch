# Постоянный ключ подписи

GitHub Actions получает секреты подписи через переменные окружения. PKCS12 появляется только во временном каталоге job и удаляется после сборки. Ключ постоянный: существующую установку нельзя обновить APK, подписанным новым несвязанным ключом.

SHA256 сертификата опубликованных 1.7–1.9:
`AB74727A44F59684045E7DB4C820BE309F886433A18A3C06F3439417F3ACBEF1`.

Ранее `configure-signing.sh` сохранял пароль рядом с зашифрованным PKCS12. Теперь скрипт принимает **существующий** ключ, получает пароль через macOS login Keychain либо скрытый ввод в терминале и передаёт секреты `gh secret set` через stdin. Он не создаёт парольный файл и не генерирует замену ключу.

Для переноса старого парольного файла в Keychain на доверенном Mac с JDK 17:

```sh
python3 scripts/signing-keychain.py protect /secure/TgWatch-signing-backup \
  --expected-certificate AB74727A44F59684045E7DB4C820BE309F886433A18A3C06F3439417F3ACBEF1
```

Скрипт проверит исходный сертификат, сохранит пароль в Keychain, прочитает его обратно и проверит тот же ключ **в отдельном процессе**. Только после всех проверок он удалит `tgwatch-signing-password.txt`. При запрете доступа, заблокированном Keychain, несовпадении сертификата или ошибке проверки парольный файл остаётся на месте. Пароль не попадает в аргументы команд и журналы.

Проверка восстановления без печати пароля:

```sh
python3 scripts/signing-keychain.py verify /secure/TgWatch-signing-backup \
  --expected-certificate AB74727A44F59684045E7DB4C820BE309F886433A18A3C06F3439417F3ACBEF1
```

Храните резервную копию **зашифрованного PKCS12 и login Keychain**, либо сам пароль в отдельном доверенном менеджере паролей. Одного PKCS12 без пароля недостаточно для восстановления. GitHub не позволяет прочитать уже записанные signing secrets обратно. Пути к PKCS12 входят в имя Keychain item; после переноса каталога используйте исходный путь либо безопасно перенесите запись через Keychain Access.

В ограниченной среде разработки проверка записи в Keychain получила `100001 / Operation not permitted`. Поэтому реальная локальная копия пароля пока не переносилась и не удалялась. Запуск `protect` вне этой среды остаётся необходимым шагом владельца; это ограничение окружения, а не смена ключа подписи.
