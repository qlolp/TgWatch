# SDK37 / AGP9: эксперимент совместимости

Это отдельная пробная пересборка исходников 1.24.0 (`de16da3`), а не утверждённая
миграция production или новый релиз. Рабочая ветка `claude/project-thread-s0ejzl`
не изменяется. Результаты конкретного коммита фиксируются в draft PR и его CI.

## Выбор версий

| Компонент | Стабильная база | Эксперимент |
|---|---|---|
| Android Gradle Plugin | 8.13.2 | 9.2.1 |
| Gradle | 8.14.6 | 9.4.1, включая Wrapper JAR и скрипты |
| compileSdk телефона | 36 | 37 (`platforms;android-37.0`, revision 2) |
| Android Build Tools | 36.0.0 / 35.0.0 | 37.0.0 для телефона и Wear |
| AndroidX Core телефона | 1.16.0 | 1.19.1 |
| Kotlin Gradle Plugin | 2.4.21 | объявление JVM-плагина 2.4.21 сохранено |
| JDK / JVM bytecode | 17 / 17 | 17 / 17 |

AGP9.1.1 требует Gradle9.3.1, но официально поддерживает только API36.1.
AGP9.2.1 требует Gradle9.4.1 и поддерживает API37.0. Это подтверждено
`SdkConstants.GRADLE_LATEST_VERSION` и `MAX_SUPPORTED_ANDROID_PLATFORM_VERSION`
из опубликованных Google исходников
[common32.1.1](https://dl.google.com/dl/android/maven2/com/android/tools/common/32.1.1/common-32.1.1-sources.jar)
и [common32.2.1](https://dl.google.com/dl/android/maven2/com/android/tools/common/32.2.1/common-32.2.1-sources.jar).
Предупреждение неподдерживаемого compileSdk не подавляется.

В AGP9 включена встроенная поддержка Kotlin. Из Android-модулей и корневого
plugins-блока убран `org.jetbrains.kotlin.android`; JVM-модуль сохраняет свой
плагин. Временные флаги `android.builtInKotlin=false` и `android.newDsl=false`
не используются. Встроенный Kotlin, показываемый `gradlew --version`, относится
к самому Gradle и не доказывает версию компилятора приложения.

`targetSdk` телефона остаётся 36, Wear — 35; `minSdk` остаются 26 и 30.
Wear продолжает компилироваться против SDK35. Обновление Android runtime
поведения через target37 — отдельная работа после проверки совместимости.

## Воспроизведение

Нужен JDK17 и Android SDK с принятыми лицензиями. Android command-line tools23
успешно устанавливают новые пакеты; старый manager19 видит их, но предупреждает
о несовпадении версий SDK XML. Для CI список пакетов и BUILD_TOOLS обновлены
вместе; SDK35/36 сохранены для прежних fixtures.

```bash
bash scripts/ensure-android-sdk.sh
python3 -m unittest scripts.tests.test_sdk_setup -v
bash ./gradlew :probe-core:test :probe-core:detekt \
  :app:detekt :app:testDebugUnitTest :app:targetBackupHeapTest :app:lintDebug \
  :app:assembleDebug :app:assembleRelease :app:assembleDebugAndroidTest \
  :app:dependencyInventory :app:generateReleaseSbom \
  :wear:testDebugUnitTest :wear:detekt :wear:lintDebug \
  :wear:assembleDebug :wear:assembleRelease :wear:assembleDebugAndroidTest \
  :wear:dependencyInventory :wear:generateReleaseSbom --no-daemon --console=plain
```

Успешный `gradlew help` подтверждает только конфигурацию, а не APK, lint или
unit-тесты. Полная CI-матрица проверяет API26/29/35/36 и самостоятельный Wear OS3.
Проверка runtime на Android17/API37, production-подпись, signed upgrade и
публикация этим экспериментом не подтверждаются. Версия приложения, форматы
данных и настройки подписи не меняются; выпуск уже опубликованной 1.24.0
повторно запрещён обычной release policy.
