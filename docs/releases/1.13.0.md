# 1.13.0 — Android 15, automation and local diagnostics

Source version `1.13.0`, deterministic Android code `1013000`, target API35.
This is a prepared release description; it does not claim publication.

- Preserve the English/Russian UI, per-app language selection and opt-in daily
  summary introduced in 1.12. Improve chart/status accessibility, contrast,
  touch targets, large-font layout and Android 15 system-bar insets.
- Add disabled-by-default explicit broadcast automation: token-authorized
  GET_STATE and rate-limited CHECK_NOW for an already running monitor.
  Credential management has its own private screen. Tokens stay outside
  portable backups, diagnostics and platform backup/transfer rules.
- Export bounded, redacted local diagnostic JSON through Android's file picker.
  Scheduling counters measure late arrivals and observed idle state without
  attributing every delay to Doze. No automatic telemetry is sent.
- Show a compact ongoing-notification availability progress indicator with the
  same observed-time denominator as existing daily statistics.
- Fix daily-summary scheduling after a daylight-saving-time gap; respect quiet
  delivery and disabled notifications and avoid duplicate scheduled summaries.
- Replace run-number-based versions with checked-in SemVer and exact matching
  tags. Publication checks main ancestry and upgrade ordering before signing;
  existing tags/assets and production certificate/upgrade gates remain.
- Add editor configuration, pinned baseline-based Detekt and disabled F-Droid
  packaging metadata with documented signing/reproducibility limitations.

The portable backup format remains TGWB v2 with readers for published TGWB v1
and local TGWBKUP1. Monitoring remains stopped after restoration. Existing
bounded network probes, seven-day history, Direct Boot and independent alert
settings are preserved.

Development APKs use a development certificate and cannot replace a production
installation. A production update requires the existing signing identity and
successful release gates. F-Droid submission, acceptance and distribution are
separate steps.

Validation evidence will be recorded in `1.13.0-verification.md` once the
complete test and review checks have finished.
