# TG Монитор 1.10

Подготовка выпуска. Эта запись описывает изменения и ограничения; результаты проверок и факт публикации фиксируются отдельно.

- MTProto-проверка теперь требует полный корректный `resPQ`: заголовок, server message id, случайный nonce, server nonce, TL pq с выравниванием и вектор fingerprints. Abridged frame ограничен 4096 байтами. Это начальный unauthenticated обмен без аккаунта; доставка сообщений и аутентичность сервера не проверяются.
- Резервная копия переносит пользовательские настройки, историю и журнал через системный выбор файла. AES-256-GCM, PBKDF2-HMAC-SHA256 и пароль 8–1024 символа; пароль не сохраняется. При экспорте ввод подтверждается.
- Восстановление сначала показывает дату и объём, затем заменяет текущие данные после подтверждения. Неверный пароль и повреждённый файл отклоняются до изменения данных. Мониторинг остаётся выключенным до ручного запуска; последнее состояние устройства, последний OK и разрешения ОС не переносятся. Прерванная замена завершается из локального журнала транзакции при следующем старте процесса.
- CSV-импорт принимает текущий семиколоночный и старый пятиколоночный UTC-формат, показывает предварительный просмотр и заменяет только историю. UNKNOWN-строки пропускаются: формат не различает реальную неопределённую проверку и сгенерированный пробел. Если не осталось наблюдений текущей временной эпохи, импорт даёт пустую историю. Настройки и журнал сохраняются; диагностическое состояние и последний OK сбрасываются. Мониторинг после импорта остаётся выключенным.
- Сводка показывает число проверок каждого статуса, завершённые полностью наблюдённые сбои и среднее время восстановления (MTTR). Учитываются только эпизоды, начавшиеся переходом OK→TG_DOWN и завершившиеся свежим OK в выбранном окне. PARTIAL может продолжать сбой; пробел, UNKNOWN/NO_NETWORK, другая временная эпоха и обрезанные/текущие эпизоды исключаются. При отсутствии подходящих эпизодов MTTR не показывается.
- Тихие часы задаются по минутам, например 23:15–08:45, в локальном часовом поясе. Начало включено, конец исключён, одинаковые границы отключают интервал. Старые часовые настройки сохраняются как HH:00; системный DND учитывается.
- Виджет отдельно сохраняет время последнего опубликованного OK. PARTIAL и ошибки его не заменяют; перезапуск сохраняет его, а перевод часов назад отмечается явно.
- История синхронизирует append при смене статуса и на очередной записи после 60 с с прошлого sync. Несинхронизированные записи могут быть потеряны при отключении питания; остановка, компактизация и замена используют отдельное сохранение.

Копия ограничена 8 МиБ расшифрованных данных, 65 000 наблюдениями и 150 строками журнала до 4096 символов. Семидневное хранение сохраняется после импорта и восстановления. CSV не шифруется и не переносит настройки или журнал. Пароль резервной копии восстановить нельзя.

## Обновление и публикация

Production-выпуск использует постоянный ключ, введённый с `v1.7.28`. Перед публикацией предусмотрены сравнение сертификата с настоящим `v1.8.33` и проверка обновления без очистки данных. Старая 1.6 с утраченной debug-подписью не становится совместимой с новым ключом; перенос возможен только из установленной версии с доступным экспортом.

Публикация выполняется вручную в `Build APK` на `main` с `publish=true`, после предусмотренных проверок и успешного Trivy scan этого запуска. Тег — `v1.10.<run_number>`, Android versionCode — `run_number + 100`; локальный код версии — 11. Старый запуск не заменяет более новый `latest`. Существующий опубликованный тег допускает только полностью идентичный повтор; draft, неполные или изменённые файлы требуют явного разбора. Тег без release, указывающий
на другой commit, также отклоняется до создания release. Новый push не отменяет уже выполняющуюся публикацию.

Вместе с `TgWatch.apk` предусмотрены SHA-256, CycloneDX SBOM из разрешённых release runtime artifacts и JSON-отчёт Trivy. HIGH/CRITICAL vulnerabilities, ошибка или недоступность сканера останавливают gate. Trivy 0.75.0 запускается с `--list-all-pkgs`; новый отчёт должен соответствовать artifact и
покрывать package inventory из SBOM. Наличие файлов SBOM само по себе не является
подтверждением успешного scan. Локальный scan 10 октября 2026 года на официальной GHCR
базе прошёл для двух runtime-библиотек без HIGH/CRITICAL; GitHub workflow этим не подтверждён.

Настройка signing: `scripts/configure-signing.sh restore <backup-directory>` использует существующие ключ и пароль, требуя alias `tgwatch` типа `PrivateKeyEntry`,
и не генерирует новые. Файл только с сертификатом отклоняется до изменения Secrets. `init` предназначен для первоначального ключа; замена существующих Secrets возможна только с явным флагом в этом режиме. Для обычного выпуска ключ заново не создают.
