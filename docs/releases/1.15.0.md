# 1.15.0 — alert timers, prompt status, history and incidents

Source version `1.15.0`, deterministic Android code `1015000`, target API35.
This description prepares a release; it does not claim production APK publication
or F-Droid acceptance.

- A one-hour alert pause uses elapsed time and the device boot identity. Clock
  corrections cannot extend it or revive an expired pause. It survives process
  restarts within the same boot; **rebooting ends the pause**. The main screen
  offers "Resume alerts", which cancels only this timer. Quiet hours, system DND,
  event preferences and Android channel settings still apply. Mute state stays
  on this device and is excluded from portable backups.
- Telegram's primary result is published before optional EXTRA checks finish.
  Their later results only enrich diagnostics for the same check and network;
  older completions after a new check, network change, stop or restore are discarded.
  The existing bounded pools remain in use, including when DNS ignores interruption.
- Unchanged history preparation is cached. Statistics and chart buckets are
  prepared on a bounded worker; rapid period changes replace pending work, and
  paused or destroyed screens discard late responses.
- Incident cards show observed onset/recovery, partial availability, lost internet
  and unknown intervals separately. Clipped or unobserved starts and missing
  recovery are explicit. Only the current clock epoch and the latest 100 episodes
  within seven days are shown. Sharing is a deliberate action and contains times
  and duration totals, without endpoints, addresses, network identifiers or secrets.
  These cards do not change MTTR or turn missing data into confirmed outage time.
- Webhook attempts have a 10-second total result deadline and request cancellation
  when it expires. A stuck transport still occupies the single physical slot until
  it actually ends. Private settings show sanitized delivery health for this process;
  no URL, response body or raw exception is displayed or exported with it.
- CI waits for ADB reconnection, actual root identity and boot completion within
  finite command and overall deadlines. Permanent errors remain failures.

Seven-day retention, the 65,000-row limit, history CSV and the TGWB v2 envelope
with JSON payload `formatVersion=2` are unchanged. Supported older backups remain
readable. See [backup details](../backup.md).
