## Android and CI status

Fresh local Android35 XML records 44 tests: 42 passed, one intentional
notification-denied assumption skip and one clipboard-focus failure. The latter
was caused by Launcher3/System UI ANR dialogs covering the resumed application;
WindowManager and input focus confirmed this. The two real Close app buttons
were used to recover the disposable emulator. The unchanged four-test automation
class then passed: four tests, no failures, errors or skips. Its foreground-copy,
sensitive clipboard, cleanup and saved-state privacy assertions remain intact.

The [first CI run](https://github.com/qlolp/TgWatch/actions/runs/38163826298),
for exact source `6da94f9`, completed: build and full Android35 smoke passed;
Android29 failed during `UiAccessibilityTest` initialization. Compiled Kotlin
lambda signatures exposed API33 `LocaleManager` to JUnit reflection before the
test's SDK guard. Moving that body into a private API33 helper removes the type
from all reflected test signatures while preserving all six test entry points.
Fresh compilation and javap verification passed. This changes test loading, not
application behavior. SDK-specific checks now use explicit assumptions, so
unsupported assertions are counted as skipped rather than passed.

The [matrix rerun for f1871ed](https://github.com/qlolp/TgWatch/actions/runs/38164882706)
completed both full smoke jobs successfully. Its new XML reporter establishes:

| Platform | Tests | Passed | Failures/errors | Skipped |
| --- | ---: | ---: | ---: | ---: |
| Android29 | 44 | 41 | 0/0 | 3 |
| Android35 | 44 | 43 | 0/0 | 1 |

The common skip requires a separately disabled notification permission; that
path passed in its dedicated run. The two additional Android29 skips require
API30 insets and API33 per-app locale selection. Smoke also exercised the legacy
data upgrade, network loss/recovery, Doze, locked boot and subsequent unlock.

The build job in that rerun failed only the test-helper annotation rule
`UseSdkSuppress` (one error); the helper now uses `@SdkSuppress`. A standalone UI
replay also exposed a fresh-install notification dialog that paused the Activity;
the UI fixture now explicitly grants and verifies permission before launching
its Activity scenarios. A second isolated replay exposed an already running
foreground monitor: disabling its preference alone did not stop that service.
The locale/inset fixtures now await teardown and assert both the disabled
preference and stopped runtime before launching the Activity. Application code
and all UI assertions are unchanged.

Final local validation passed after these fixture corrections: full source
build, 200 JVM tests, Detekt and lint (zero errors/19 warnings), plus all six
focused Android35 UI tests with no failures, errors or skips. The final fresh
helper discovery passed 93 tests; the separate audit/signing helpers passed four
more. The rebuilt application APK matches the verified artifact byte for byte.
The final pushed head's required checks are linked from
[PR #15](https://github.com/qlolp/TgWatch/pull/15/checks); that head's CI outcome
must be read there rather than inferred from the earlier matrix results.

GitHub job logs were obtained through `gh run view`; direct log/artifact ZIP
redirects were denied by the cloud's storage-host access policy. The initial
Android logs' Starting/Finished totals differ, so no exact CI passed count is
inferred from them. Safe bounded annotations now expose actual XML counts and
failure identifiers; raw XML/HTML/logcat artifacts are not claimed redacted.
Do not interpret a pending check as passed or a permission skip as validation
of the denied path.
