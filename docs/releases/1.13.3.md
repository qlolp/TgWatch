# 1.13.3 — backup tail and check scheduling

Source version `1.13.3`, deterministic Android code `1013003`, target API35.
This is a prepared release description; it does not claim APK publication or
F-Droid acceptance.

- Backup export captures one time for `createdAt` and the history it contains.
  The last check's predicted coverage (up to one interval plus 15 seconds) is
  clipped at that time, so a restored copy does not present the transfer period
  as observed. Restore still applies the copy's intervals unchanged.
- Repeated capability callbacks for the same validated default network, such as
  signal or bandwidth updates, no longer bump the check revision. A good result
  is not turned into UNKNOWN and no extra check is scheduled. A new network, its
  loss, and validated or captive-portal transitions still invalidate the result.
- A manual or settings check request that arrives while a check runs is no longer
  replaced by the normal interval when that check finishes. All such requests
  coalesce into exactly one immediate follow-up check. An alarm arriving during a
  check is satisfied by that check and does not queue another one.

The backup format is unchanged from 1.13.2: TGWB v2 with JSON payload
`formatVersion=2`. See [backup details](../backup.md).
