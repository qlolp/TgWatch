# 1.14.0 — honest probes, consent-based exact alarms and a verifiable release

Source version `1.14.0`, deterministic Android code `1014000`, target API35.
This is a prepared release description; it does not claim publication.

- Probe every production data centre in both address families, so an IPv6-only network no
  longer reads as a partially reachable Telegram. The probe pool now fits the whole batch.
- Ask the user for the exact-alarm permission on Android 13+ instead of holding
  `USE_EXACT_ALARM`, which Play reserves for alarm and calendar apps and which granted the
  permission silently, hiding the setup checklist. Monitoring keeps its inexact-alarm
  fallback where the permission is refused.
- Persist the last state on status changes and at most once a minute otherwise, and stop
  blocking the check thread on last-success persistence.
- Answer outage, partial and recovery notifications with Check and Stop actions.
- Send the daily summary only while monitoring is enabled.
- Refresh the screen as soon as the service publishes a result instead of waiting for the
  one-second ticker, and report the built application version as the probe User-Agent.
- Shrink and obfuscate the release build with R8 while keeping manifest components and
  persisted enum names; the debug build and its tests are unchanged.
- Select the signed-upgrade baseline from the published releases and verify its checksum,
  and re-check the APK checksum, signature and manifest version right before publication.
- Pin every GitHub action to a commit, the Gradle distribution to its checksum and the
  release tooling to a hash-locked requirements file; add Dependabot updates and job
  timeouts, and record the OSV database state each audit run observed.

The portable backup format remains TGWB v2 with readers for published TGWB v1 and local
TGWBKUP1. Monitoring remains stopped after restoration. The seven-day history, Direct Boot
support, independent alert settings, automation API, local diagnostics and opt-in webhooks
introduced in 1.13 are unchanged.

Validation evidence and outstanding checks are recorded in
[1.14.0-verification.md](1.14.0-verification.md) once the release run completes.
