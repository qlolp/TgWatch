# 1.16.0 — reliable monitoring and private settings

Source version `1.16.0`, deterministic Android code `1016000`, target API35.
The production certificate and supported backup/history formats are preserved.

- Interrupted checks no longer publish incomplete results or dismiss an existing
  outage alert. The previous observation remains visible with its original time;
  a short retry runs without recording an unmeasured result as fresh history.
- A diagnostic last-success write failure no longer discards a successful probe.
  Network revisions are checked at the publication boundary so stale results cannot
  slip through a callback race.
- Notification statistics load on the monitor worker. Foreground startup uses the
  available cached snapshot; scheduled and manual daily summaries run on a bounded
  background worker.
- Webhook settings explicitly show when an unfinished cancelled/timed-out request
  blocks delivery. Changing settings cannot hide that physical request or open a
  second one. A restart may be necessary if the platform transport never returns.
- Automation settings display a masked token; the explicit sensitive-copy button
  remains available. Rejected CHECK_NOW requests do not consume the throttle budget;
  failed throttle persistence cannot launch a check. Invalid webhook addresses and
  storage failures have different messages.
- Password and custom-address dialogs prevent screenshots. Custom addresses disable
  view-state saving and autofill, and their inclusion in encrypted backups is explicit.
  Settings and tile age-only polling is less frequent; status broadcasts remain prompt.
- Reviewed CI/test dependencies are updated, with regenerated artifact-hashed Python
  tooling. Major Gradle/AGP changes require a coordinated migration.
- Publication verifies the source checkout, checksum, APK certificate, package and
  version immediately before release creation. All six uploaded assets are downloaded
  again and compared with the original bytes. Existing releases are never overwritten.

No automatic external telemetry, GET_STATE API rewrite or framework migration is
included. F-Droid metadata remains a disabled packaging candidate, not a published listing.
