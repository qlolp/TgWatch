# TG Монитор 1.11 — подготовка выпуска

1.11 объединяет опубликованную 1.10.47 и локальные доработки. Локальные сборки, JVM/helper
проверки, Android instrumentation, development-key upgrade/cold replay и Trivy завершены;
OSV заблокирован.
[Отчёт проверки](1.11-verification.md) отделяет локальные PASS от незавершённых release gates. Production-подпись,
GitHub CI и публикация 1.11 не заявлены.

- Сохранены независимые уведомления и звук TG_DOWN, PARTIAL и восстановления, отдельные Android channels и прежние opt-ins. PARTIAL по умолчанию выключен; тихие часы и DND подавляют звук/вибрацию.
- Тихие часы задаются по минутам в локальном timezone; часовые настройки читаются как HH:00. Начало включено, конец исключён, равные границы отключают интервал. Виджет отдельно сохраняет время последнего опубликованного OK; PARTIAL/ошибки его не меняют, clock rollback отмечается явно.
- Новый экспорт TGWB v2 использует PBKDF2-HMAC-SHA256 (600 000 iterations), AES-256-GCM и ограниченный JSON snapshot до 8 МиБ. Пароль экспорта — 12–256 символов с подтверждением. Читаются опубликованный бинарный TGWB v1 и прежний локальный TGWBKUP1; новый экспорт создаёт только v2.
- Restore заменяет пользовательские настройки, историю и журнал после проверки/preview/подтверждения. Неверный пароль и malformed input не меняют данные или работающий monitoring. Pending replay поддерживает оба прежних private journal formats и завершается до мониторинга; после restore monitoring запускается вручную. Диагностика, последний OK, OS permissions и enabled state не переносятся.
- CSV импортирует только историю, сохраняет настройки/журнал и оставляет monitoring выключенным. UNKNOWN rows опускаются, чтобы gaps не стали выполненными checks. Сохранены семидневное хранение и текущая clock epoch даже при полностью устаревшей истории.
- Сводка содержит per-status checks и точное среднее latency. Полностью наблюдённый TG_DOWN для MTTR может продолжаться через PARTIAL до свежего OK; отсутствие сети, gaps, clipped/ongoing episodes и clock changes разрывают покрытие. Это уточнение по сравнению с опубликованной 1.10, где PARTIAL исключался из MTTR.
- Сохранены полная bounded resPQ/TL/framing-проверка и shared deadlines/cancellation. MTProto остаётся unauthenticated greeting без аккаунта, RPC или проверки доставки сообщений.
- CI объединяет schema-valid CycloneDX 1.6 runtime SBOM с artifact SHA-256/Trivy HIGH+CRITICAL gate и OSV audit точных runtime/test Maven versions. Недоступность/ошибка audit блокирует gate, а не объявляется чистым результатом.
- Signing использует только существующий ключ с alias/expected-certificate проверкой и macOS Keychain. Ручные main-публикации сериализованы, существующие tags/assets immutable, старый versionCode не продвигает latest.

Лимиты snapshot: 65 000 наблюдений и 150 строк журнала по 4096 символов. CSV — plaintext;
для переноса настроек/журнала нужен зашифрованный backup. Пределы старых форматов и legacy
fallback: [backup](../backup.md). Защита существующей подписи: [signing backup](../signing-backup.md).

Local versionName 1.11, versionCode 12; CI versionCode — проверенный `run_number + 100`,
тег — `v1.11.<run_number>`. Upgrade baseline — неизменяемый опубликованный `v1.10.47`
(SHA-256 `efd2147dae453c12288da5b3f33840f3dfb2f6b85032411f348fabb5e8e009d1`).
Production certificate/upgrade gate требуется в CI; локальная development-подпись этого
не доказывает. Перед выпуском должны завершиться JVM/helper tests, lint, APK assembly,
Android scenarios и оба audits. Текущее состояние gates: [отчёт проверки](1.11-verification.md).
