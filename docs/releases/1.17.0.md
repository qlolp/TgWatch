# 1.17.0 — responsive automation state

Source version `1.17.0`, deterministic Android code `1017000`, target API35.
The production certificate and supported backup/history formats are preserved.

- `GET_STATE` (and ordered `CHECK_NOW` result snapshots) serve a process-local
  cache for one second, so polling clients avoid repeated prefs and restore-journal
  work on every request.
- Fresh snapshot computation runs on a dedicated worker via `goAsync()`, not on the
  main broadcast thread. Unauthorized and invalid requests still fail closed
  synchronously with no extras.
- When the cache has expired, a 200 ms compute gap prevents flood recomputation.
  Clients that exceed the gap without a fresh cache receive `RESULT_RATE_LIMITED`
  (`4`), the same code already used for `CHECK_NOW` throttling.
- API fields and `api_version=1` are unchanged. Webhook orphaning, Gradle artifact
  verification and major toolchain migration remain separate work.

See [automation.md](../automation.md) for client guidance.
