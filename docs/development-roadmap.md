# Реализованные возможности и решения развития

## Текущее состояние

Проект включает независимые цели Telegram, Matrix, WhatsApp Web и до пяти HTTPS;
их обзор без общего cross-service процента, отдельные истории с хранением 7/30/90 дней
и rollup-агрегатами, наблюдаемость покрытия и инцидентов, региональные профили с
локальным журналом и одноразовым ожиданием, которое восстанавливается после
перезагрузки без старых свидетельств. Также есть настройки энергосбережения, виджеты,
самостоятельное Wear OS-приложение, нативное macOS-меню, зашифрованные переносимые
бэкапы TGWB v4/v5 и локальная диагностика.
Вебхук поддерживает событийный JSON и отдельный JSON v2 с heartbeat и истечением
свежести в Home Assistant.
Подробные проверенные версии и артефакты выпуска приведены в release notes и
GitHub Releases; локальная сборка не означает публикацию. Подготовка F-Droid
отделена от принятия каталогом.

Ниже сохранены исторические причины решений. Реализованные функции заменили прежние
ограничения: мультисервис уже реализован, webhook поддерживает JSON, а отсутствие
runtime-зависимостей больше не является аргументом против проверки графа.

## История решений

В 1.17.2 сборка переведена на Gradle 8.14.6, AGP 8.13.2 и Kotlin 2.4.21 одним шагом
(Dependabot теперь присылает эти обновления одной группой). Результат проверки, сеть
которой сменилась во время проб, больше не пишется в историю как UNKNOWN: остаётся
прежнее состояние, и через секунду идёт проверка по новой сети. Две идеи из аудита после
1.15 сознательно не взяты:

- **Брошенный зависший вебхук.** Поток с запросом, который не реагирует на отмену,
  нельзя остановить; «отпустить» слот значит оставить его работать и открыть второй.
  Экран честно показывает занятый слот, а общий deadline ограничивает ожидание.
- **Строгая `verification-metadata.xml` Gradle.** Файл с хэшами пришлось бы
  перегенерировать вручную при каждом обновлении зависимостей: Dependabot его не
  обновляет. Приложения используют Kotlin stdlib,
  AndroidX и собственный :probe-core; точный выбранный состав и хэши отражены в
  отдельных SBOM телефона и часов. Wrapper и actions закреплены checksum и коммитами;
  OSV проверяет runtime/test графы, Trivy — runtime SBOM.

В 1.17 снимок `GET_STATE` кэшируется на одну секунду и считается вне главного потока
broadcast; между пересчётами действует короткий compute gap. В 1.17.1 уведомление и
виджет перерисовываются только при изменении, а будильник при включённом экране не
поднимает службу каждый интервал.

В 1.16 исправлены отмена проверок и ошибки записи диагностической отметки,
статистика постоянного уведомления и ежедневная сводка перенесены с главного потока.
Сводка ограничена независимым дедлайном и повторно проверяет разрешение доставки
после подготовки уведомления. Автоматизация скрывает токен и расходует лимит только
при принятии задачи; настройки вебхука показывают физическую блокировку и ошибки записи.
Выпуск проверяет исходные байты и Git-индекс, APK и все шесть опубликованных файлов.
[Дизайн и границы 1.16](superpowers/specs/2026-10-13-reliability-and-release-design.md).

В 1.15 завершены монотонная пауза оповещений, ранняя публикация Telegram,
фоновая подготовка истории и карточки сбоев, общий таймаут и состояние доставки
вебхука. IPv4/IPv6-пробы и инструменты выпуска описаны в
[сверке 1.15](review/release-cleanup-2026-10-12.md).

В 1.13 реализована самостоятельная часть принятого review: улучшения английского
интерфейса и доступности, target API35, постоянные SemVer-коды, проверяемый выпуск
по тегу, editorconfig/analyzer, материалы для F-Droid, ограниченный Tasker/Termux
API, локальная диагностика и наблюдаемость задержек. 1.12 с локализацией и
ежедневной сводкой сохраняется. В 1.13.1 добавлены исправления фоновой работы и
индикатора свежести. Актуальные предложения после сверки веток приведены в
[аудите 2026-10-12](review/improvements-2026-10-12.md). Результаты проверок
записываются отдельно.

## Что решено не делать и условия пересмотра

| Предложение | Решение и условие следующего шага |
| --- | --- |
| Compose | Сначала доступность и устойчивые Android lifecycle-проверки существующего экрана. Отдельная миграция потребует сравнения настроек, SAF, saved state, графика, TalkBack и large-font поведения. |
| Glance | Текущий виджет уже показывает последний OK и выполняет проверку. Glance всё равно генерирует RemoteViews; переход без новой функции не оправдывает зависимость и риск Direct Boot. |
| Coroutines/Flow | Монитор сохраняет ограниченные шестнадцать primary workers и три secondary workers, общие deadlines и закрытие socket/HTTP при отмене. Перед миграцией требуется доказать реальные stop/timeout/overlap гарантии; отмена coroutine сама по себе блокирующий socket не закрывает. |
| Hilt/Koin | Чистые policies и отдельные Android adapters уже тестируются. Ввод контейнера оправдан дополнительными зависимостями и подменами, а не размером MainActivity. |
| Robolectric | Нужен для Android adapters, когда он экономит цикл тестирования; он не заменяет реальные alarms, Doze, foreground-service и boot проверки. В текущем пакете добавлены meaningful JVM и Android regressions. |
| Несколько сервисов | Реализованы Telegram, Matrix, WhatsApp Web и один Custom HTTPS: отдельные идентификаторы, истории, настройки и оповещения. Старые данные мигрируют в Telegram; TGWB v4 переносит все цели и выбранный retention, сохраняя чтение поддерживаемых старых форматов. Дополнительные цели выключены по умолчанию. Несколько независимых Custom HTTPS — отдельное расширение модели идентификаторов. |
| Room / расширение истории | Хранение 7/30/90 дней и минутные/пятиминутные rollups уже реализованы в bounded durable storage. Room сам по себе не нужен для этого диапазона; пересмотр оправдан более сложными запросами или неограниченным retention после измерений памяти, миграций CSV/epochs/restore и времени агрегаций. |
| Webhook / Matrix / bot / ntfy | Реализованы TEXT, JSON v1 и отдельный JSON v2 с heartbeat и примером Home Assistant TTL. Общий физический слот, 10-секундный deadline, фильтры и изоляция поколений сохраняются. Адрес приватный и исключён из бэкапа; интеграция выключена по умолчанию. MQTT, несколько получателей и прямые bot-адаптеры остаются отдельными расширениями. |
| Sentry / ACRA | Локальный CrashJournal и явный обезличенный diagnostic export уже реализованы. Для remote crash reporting нужны согласованный оператор, retention, consent и проверка redaction. Шифрование бэкапа не описывает безопасный транспорт телеметрии. |
| HTTP API на localhost | Излишний постоянно работающий сервер; localhost доступен другим приложениям. Реализован ограниченный explicit-broadcast API с authentication. |
| Удалённый dc.json | Даже подсказки меняют маршруты запросов: нужны trusted source, границы, rollback и встроенный fallback. resPQ не аутентифицирует сервер. Сейчас сохраняются официальные embedded DC и локальная диагностика. |
| HMAC / QR secret | AES-GCM уже проверяет целостность и позволяет офлайн проверять догадки пароля. Дополнительный HMAC этого не устраняет. Отдельный секрет должен участвовать в derivation AES-key, а его потеря меняет восстановление; существующий portable format сохраняется. |
| Hardware-backed release signing | Android Keystore на телефоне относится к ключам устройства, а не замене production build-signing key. Смена сертификата прервёт обновления. Существующий ключ и continuity gate сохраняются. |
| NTP | Дополнительные внешние запросы и отдельная trust/time модель. Monotonic deadlines, epochs и неизвестные интервалы уже сохраняют честную историю; сетевое время не должно автоматически переписывать наблюдения. |
| F-Droid listing | Для тега 1.20.1 локально проверены readmeta/lint, нормальная сборка и совпадение unsigned APK; это историческое evidence только для указанного тега. Текущий recipe указывает на 1.23.0, остаётся выключенным и не заявляется проверенным для этой версии. Автоматические обновления и принятие каталогом — отдельные шаги после review сопровождающих. |

Второй проход по 1.15.0 (зависший слот вебхука, статистика истории на главном потоке,
токен записи в рабочем каталоге релизной джобы, мажорные Dependabot PR тулчейна) собран
в [аудите после 1.15](review/improvements-after-1.15.md) с точными патчами workflow
в [workflow-hardening](review/workflow-hardening.md).

Эти строки описывают границы выполненной итерации; они не означают, что будущие
подсистемы реализованы или публикации состоялись.
