# F — Standalone Wear OS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Выпустить самостоятельные измерения с часов, Tile и complication без зависимости от телефона.

**Architecture:** Общее переносимое ядро сохраняет телефонную семантику. Watch controller делает только user-initiated bounded checks, а поверхности читают локальный кэш.

**Tech Stack:** Kotlin/JVM 17, Android Views, Gradle 8.14.6, AGP 8.13.2, Kotlin 2.4.21, JUnit 4; дополнения указаны в задачах.

**Spec:** [Утверждённая спецификация](../specs/2026-10-17-wear-design.md), [общие ограничения](../specs/2026-10-17-growth-design.md).

## Global Constraints

- Телефон: Android API 26+, compile/target API 35; Kotlin и существующий Views UI.
- Один foreground-сервис; нет сервера автора, учётной записи или фоновой телеметрии.
- Дополнительные цели и внешние интеграции выключены по умолчанию.
- Недоступность измерения, отсутствие сети и измеренный сбой сервиса различаются.
- `claude/project-thread-s0ejzl` не изменяется, не удаляется и не используется как рабочая ветка.
- Существующие API v1, виджет Telegram и чтение бэкапов v1/v2 сохраняются.
- Новые пользовательские строки добавляются на русском и английском.
- Wear: API30+ (Wear OS3+), applicationId ru.tgwatch.wear, compile/target35.
- Максимум4 физических watch-запроса, общий deadline8 секунд, stale после3 минут.
- Нет постоянного foreground-мониторинга или exact alarms на часах по умолчанию.
- Нет Google Play Services/Data Layer в телефонном APK; измерения явно сделаны с часов.

## Review Focus

- Извлечение core случайно меняет телефонный набор/локализацию/Network binding (Task 1).
- Частичный набор watch probes ошибочно объявляет общий TG_DOWN (Task 2).
- Activity restart и зависшие native запросы обходят physical limit (Task 2).
- Tile/ambient/complication refresh выполняет скрытые сетевые запросы (Task 3).
- Phone SBOM/подпись/отчёт случайно прикладывается как Wear evidence (Task 4).
