# B. Покрытие, здоровье мониторинга и JSON-вебхук

Статус: утверждено пользователем 17 октября 2026 года. Зависимость: [A](2026-10-17-reliability-design.md).
Общие правила: [программа развития](2026-10-17-growth-design.md).

## Покрытие наблюдениями

Существующий uptime не меняет знаменатель: OK / (OK + DOWN + PARTIAL).
Рядом показывается, на какой части выбранного окна подтверждена оценка сервиса:
`(okMs + downMs + partialMs) / windowMs`. Отдельно видны время без сети и время без
измерений. NO_NETWORK не выдаётся за доступность или недоступность Telegram.

Пример: «Доступность 100%; оценка сервиса за 20 минут из 24 часов».
При нулевом покрытии отображается «Недостаточно данных», а не 0% или 100%.
Clock rollback не объединяет перекрывающиеся epochs. Значения ограничены длиной
окна и не оценивают ненаблюдавшееся время. Это полнота данных, не статистическая
вероятность или гарантия доступности.

## Здоровье самого мониторинга

Отдельный блок показывает: последнее завершённое измерение, возраст/свежесть,
длительность текущей проверки, неначатые пробы, занятые физические слоты,
доступность истории и состояние сохранения. Счётчики опираются на факты
ScheduleDiagnostics и A; задержка не приписывается Doze без прямого свидетельства.

Настоящий сбой сервиса и неработающая проверка имеют разные тексты и обозначения.
Статистика и состояние публикуются immutable-снимком с revision. Загрузка истории
и агрегация выполняются в фоне; устаревший ответ не заменяет снимок нового окна.
Локальный обезличенный export не содержит URL, IP, токены или тела HTTP-ответов.

## Контракт вебхука

Один адрес; прежний `text/plain` остаётся форматом по умолчанию. JSON выбирается
явно и отправляется как `application/json; charset=utf-8`. URL, формат и фильтры
образуют одно поколение настроек в приватном credential-хранилище.

JSON schema_version=1 содержит только:

```json
{
  "schema_version": 1,
  "service_id": "telegram",
  "event": "unreachable",
  "status": "DOWN",
  "previous_status": "OK",
  "checked_at_ms": 1792038600000,
  "latency_ms": null,
  "network": "WIFI"
}
```

`status`: OK, PARTIAL, DOWN, NO_NETWORK; Telegram TG_DOWN преобразуется в DOWN
только в новом JSON-контракте. Legacy API и текстовые сообщения сохраняются.
`network`: WIFI, CELLULAR, VPN, ETHERNET, OTHER или UNKNOWN; никаких SSID и IP.
`latency_ms` — подтверждённая задержка данной проверки либо null, никогда -1.
`previous_status` — предыдущий измеренный статус, а не последнее успешно
доставленное сообщение. На первом событии допустим null.

Фильтры: unreachable, partial, network_lost, recovery, network_restored.
Recovery означает восстановление после DOWN/PARTIAL; возврат из NO_NETWORK
называется network_restored. UNKNOWN и отсутствие измерения не сбрасывают
предыдущую измеренную причину. Первый здоровый OK остаётся тихой базовой точкой.
По умолчанию все перечисленные события разрешены, сохраняя текущий охват текста.
Выключение фильтра не меняет наблюдения, историю или уведомления приложения.

На monitor publication захватываются поля уже готового снимка. Синхронных чтений
History для payload нет. Устаревшее, отменённое или не полностью измеренное
отрицательное наблюдение не создаёт события. Агрегаты и пользовательские имена
целей в эту версию payload не входят.

Сохраняются HTTPS, отсутствие redirects, timeout connect/read по 5 секунд,
независимый deadline 10 секунд и один физический запрос на весь процесс.
Settings generation изолирует rate history и health старых отправок.
Одинаковый успешно доставленный статус не превращается в heartbeat; повтор
после ошибки сохраняет существующий gap 60 секунд. Нет очереди старых событий:
после освобождения слота отправляется актуальное разрешённое состояние.
Test send помечается `event=test`, не создаёт измерение и не меняет baseline.

## Home Assistant

В `docs/automation.md` добавляются точный контракт и копируемый пример HA webhook
automation с HTTPS URL, секретным webhook_id и сохранением статуса/времени события.
Пример обновляет helper «Последнее событие TgWatch» и время измерения.
Он не объявляет publisher онлайн бессрочно: событийный webhook не передаёт
heartbeat. Отсутствие сообщения не трактуется как продолжающееся OK.

Generic JSON не выдаётся за ntfy JSON API: для ntfy сохраняется текстовый режим;
его JSON endpoint и schema отличаются. Native MQTT, несколько адресов и произвольные
заголовки потребуют отдельного продолжения, а для этого HA-примера не обязательны.

## Критерии приёмки

- 20 минут OK в сутках дают uptime 100% и покрытие 20/1440; пустое окно — no data.
- Смешанные UNKNOWN/NO_NETWORK/epochs не завышают покрытие.
- Ошибка истории и задержка проверки видны отдельно от сетевого статуса.
- JSON стабильно сериализуется, latency отсутствующего измерения равна null;
  поля allowlist не пополняются диагностикой случайно.
- Фильтры, начальный OK, recovery через UNKNOWN, network_restored, retry и test
  проверяются независимо от транспорта.
- Смена URL/формата/фильтра в полёте не принимает старые callbacks и не освобождает
  физический слот преждевременно. Restore/Direct Boot не включают доставку.
- Fake HTTPS transport проверяет content-type, байты тела, отсутствие redirects,
  deadline и отмену. HA-пример проверяется fixture payload и синтаксисом YAML.
