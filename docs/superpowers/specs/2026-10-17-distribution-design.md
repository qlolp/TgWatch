# G. Узнаваемость и воспроизводимая дистрибуция

Статус: утверждено пользователем 17 октября 2026 года. Родитель: [программа развития](2026-10-17-growth-design.md).

## Проверенное состояние и цель

На 17 октября 2026 года публичная HTML-страница репозитория не содержит topics,
а description представляет стандартный текст GitHub. Число звёзд не является
фиксированным требованием и проверяется заново перед публикацией материалов.
Релиз 1.18.0 уже опубликован; metadata F-Droid остаётся disabled candidate.

Цель — понятно объяснить сценарий приложения и дать проверяемую установку.
Нельзя обещать звёзды, охват, одобрение магазина или независимую reproducibility.

## Материалы и metadata

Предлагаемый GitHub description:
«Private Android reachability monitor for Telegram. Local history, alerts and diagnostics.»
После выхода мультисервиса текст обновляется, а не обещает его раньше релиза.
Предлагаемые topics: android, kotlin, telegram, network-monitoring, privacy,
network-diagnostics, uptime-monitoring, fdroid.

README RU/EN получает короткий сценарий, явные границы измерений, прямую ссылку
на актуальный подписанный APK, checksum/сертификат, скриншоты и различие GitHub
release/F-Droid candidate. Новые возможности описываются только после реализации.
Скриншоты делаются с fixture-данными без личных endpoints и токенов.

Текущие docs/fdroid.md ошибочно описывают старый тулчейн 8.10.2/8.7.3/2.0.21 при
фактических 8.14.6/8.13.2/2.4.21; документация и рецепт сверяются с точным тегом.
Рассуждение roadmap об отсутствии runtime dependencies корректируется по
разрешённому runtime inventory; наличие Kotlin stdlib не скрывается.

Существующие issue/PR templates проверяются и дополняются только недостающими
полями: версия/API, состояние сети, ожидаемое/наблюдаемое поведение и безопасный
отчёт диагностики. Логи с секретами не предлагаются как обязательное вложение.
Метки good first issue/help wanted добавляются к подходящим задачам, а не к
неразобранным архитектурным миграциям или всем багам подряд.

## F-Droid и внешние изменения

Кандидат-рецепт проверяется fdroid readmeta/lint и независимой unsigned source
сборкой с актуального тега. Проверяется состав лицензий/SBOM и отсутствие
proprietary application SDK. Проверка source build отдельно от byte reproducibility;
последняя требует независимой сборки и сравнения содержимого APK.

Готовится submission package: metadata, ссылка на тег, лицензию, исходники,
пояснение foreground monitoring/exact alarms и инструкции по подписи/миграции.
Отправка во F-Droid или публикация рекламных сообщений третьим лицам — отдельный
внешний шаг с конкретным адресатом и готовым текстом для согласования.

Description/topics/labels репозитория меняются в рамках согласованного пакета,
если GitHub предоставляет соответствующий доступ; недоступность API не мешает
подготовить точные значения и репозиторные материалы. Рабочая ветка пользователя
не изменяется ради этих действий. Принятие F-Droid не объявляется выполненным
до фактической публикации независимым каталогом.

## Критерии приёмки

- Описание README и store metadata соответствует выпущенному коду на двух языках.
- APK links, checksum, production certificate и changelog соответствуют одному тегу.
- F-Droid metadata lint/source build выполнены и записаны с версиями инструментов;
  skipped, blocked и независимая reproducibility не смешиваются с passed.
- Новые скриншоты и шаблоны не раскрывают fixture credentials/личные адреса.
- Реально сохранённые description/topics/labels проверены повторным чтением;
  подготовленные, но не применённые значения явно обозначены.
