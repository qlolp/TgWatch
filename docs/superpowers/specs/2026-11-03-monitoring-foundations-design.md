# Monitoring foundations — первый выпуск roadmap

Запрос: детализировать roadmap, начать реализацию и опубликовать изменения в GitHub. Первый законченный блок включает общий сетевой контекст, ограничение параллельных измерений и согласованное хранилище для fixture-сценариев. Остальные этапы остаются в `../plans/2026-11-03-ios-foundational-improvements.md`.

## Подход и границы

Развиваем существующие MonitorSession/ProbeRunner без изменения значений статусов и формата истории. Полная замена контроллеров или базы данных увеличивает риск без необходимой выгоды в этом блоке. Выбор реализации сделан агентом в рамках разрешения начать roadmap.

- Один NWPathMonitor на процесс публикует неизменяемое состояние всем трём потребителям: сервисам, exit lookup и VPN comparison. Каждое событие маршрута доставляется, даже если тип интерфейса не изменился. Новый подписчик сразу получает последнее известное состояние.
- Общий FIFO admission budget ограничивает число одновременно выполняющихся сервисных измерений до 2. Это консервативная стартовая настройка, не доказанный энергетический оптимум. Telegram продолжает использовать собственный внутренний лимит соединений; общий лимит относится к измерениям, не сокетам. Egress и ручное VPN-сравнение пока имеют свои существующие ограничения.
- Отмена ожидающего измерения удаляет его из очереди без запуска транспорта. Отмена выполняющегося измерения удерживает слот до окончания teardown. Ошибка транспорта освобождает слот. После отмены результат не публикуется.
- ServiceCatalog выбирает один корень данных и передаёт его каждому MonitorController, в том числе после редактирования и restore. DEBUG fixture использует временный корень и синтетические проверки; Release игнорирует --fixture. История в fixtures имеет обычное имя history-v1.json, поэтому реальный capture/restore работает над ней.
- Существующие исправления экспорта/страны/локализации входят в этот PR отдельным коммитом.
- Работа остаётся в открытой Xcode рабочей копии на новой feature-ветке: это сохраняет контекст Xcode и уже подготовленные изменения. Не менять pbxproj вручную.
- Публикация: новая ветка и PR в qlolp/TgWatch, без автоматического merge в main.

## Проверки

Тесты ядра: FIFO, лимит, отмена очереди, отмена активной работы с задержанным teardown, ошибки, replay сетевого состояния, одинаковые события маршрута, unsubscribe, нормализация типа сети, разделение директорий целей. Интеграция: BuildProject, UI fixture backup-preview (число записей не ноль), актуальная документация. Физическая установка остаётся отдельным блокером CoreDevice и не считается успешной по сборке/CI.
