# Резервная копия и перенос данных 1.13.3

В дополнительных настройках выберите экспорт резервной копии, укажите файл в системном
выборе документов и дважды введите пароль **12–256 символов**. Копия содержит пользовательские
настройки, семидневную историю и журнал событий. Пароль не сохраняется приложением;
сохраните его отдельно, восстановить забытый пароль нельзя. Шифрование и чтение выполняются
в отдельном потоке, разрешение на доступ ко всему хранилищу не требуется.

Для восстановления выберите файл и введите его исходный пароль. Приложение сначала
расшифрует и полностью проверит копию, покажет дату/число записей и запросит подтверждение
**замены** текущих настроек, истории и журнала. Отмена, неверный пароль, повреждённый,
неподдерживаемый или слишком большой файл не меняют данные и работающий мониторинг.
После подтверждённой замены мониторинг остаётся выключенным; запустите его вручную.

Последний сетевой статус, последний OK, состояние «Запущен», cooldowns, разрешения Android
и ключ подписи APK не переносятся. Независимые настройки уведомлений и звука TG_DOWN,
PARTIAL и восстановления, профили, вибрация, минутные тихие часы, переключатели проверок
других сервисов и свой публичный адрес проверки (проверяется как `https://` без логина,
параметров запроса и `#`) переносятся. Адрес вебхука и токен автоматизации — секреты и в копию
не входят; после восстановления их нужно задать заново. Системные
звук/важность каналов Android на другом телефоне настраиваются отдельно. Старые архивы
без минут сохраняют часовые границы как HH:00; отсутствующие новые флаги читаются с
прежним fallback, PARTIAL не включается автоматически.

Данные старше семи дней исключаются из рабочей истории. Если текущая эпоха целиком
устарела, служебный UNKNOWN marker сохраняет её идентичность, чтобы архивная эпоха не
стала текущей. Начиная с 1.13.2 это явная запись нулевой длительности: `UNKNOWN`,
`at=until`, `latencyMs=-1`. Она не увеличивает число проверок, не создаёт доступность
и не рисуется на графике. Реальные UNKNOWN-наблюдения положительной длительности,
включая одну миллисекунду, сохраняют своё значение. Перенос не выполняет сетевых проверок.

С 1.13.3 экспорт берёт один момент времени для даты копии и для истории: последнее
наблюдение обрезается этим моментом. Прогнозируемое покрытие до следующей проверки
не переносится как наблюдённое время. Восстановление применяет интервалы копии без изменений.

## Форматы

Экспорт 1.13.2 создаёт только **TGWB v2** с JSON payload `formatVersion=2`.
Внешний криптографический формат не меняется. Импорт читает прежний JSON payload v1
и обе разновидности 1.10, преобразуя их в строго проверяемый snapshot.

| Формат | Header и содержимое | Поддержка 1.13.2 |
|---|---|---|
| TGWB v2 | ASCII `TGWB` + byte `0x02`, salt16, nonce12, ciphertext + GCM tag16; внутри строгий JSON snapshot | Экспорт payload v2, чтение payload v1/v2; plaintext до 8 МиБ |
| Опубликованный TGWB v1 | ASCII `TGWB` + byte `0x01`, salt16, nonce12, ciphertext + tag16; внутри опубликованный бинарный payload | Только чтение существующих копий 1.10.47, прежний предел 4 МиБ |
| Локальный TGWBKUP1 | ASCII `TGWBKUP1`, big-endian iterations4, salt16, nonce12, ciphertext + tag16; внутри локальный JSON snapshot | Только чтение прежней локальной реализации, plaintext до 8 МиБ |

Все форматы используют PBKDF2-HMAC-SHA256, **600 000 iterations**, ключ 256 бит,
AES-256-GCM и случайные salt/nonce. Header аутентифицируется как AAD; полная проверка
GCM tag предшествует разбору payload и применению. Неизвестные версии и лишние/обрезанные
данные отклоняются. Новый экспорт требует 12–256 символов; старые копии открываются
исходным паролем согласно ограничениям своего формата.

Общие пределы snapshot: 65 000 наблюдений, 150 строк журнала до 4096 символов, допустимые
статусы и целые числовые значения без overflow/coercion. JSON допускает только известные
поля и whitelist-настройки; новые event flags и минуты входят в whitelist. Portable v2
и его payload version — отдельные версии: `TGWB` version определяет внешний envelope,
а JSON `formatVersion` — правила внутреннего snapshot. Writer использует payload v2,
который допускает только указанную выше zero-width UNKNOWN-отметку. Reader читает
payload v1 с прежним строгим требованием положительной длительности наблюдения;
старые UNKNOWN-записи не переопределяются как metadata.

**Новые копии требуют TgWatch 1.13.2 или новее для восстановления.** Приложения с
прежним JSON reader не понимают payload v2, даже при одинаковом внешнем TGWB v2.
Поддержка чтения старых копий и параметры шифрования сохраняются.

## Прерывание восстановления и CSV

Приватный durable journal фиксируется после валидации и подтверждения. Замена нескольких
локальных хранилищ повторяется идемпотентно после прерывания; мониторинг не публикует
результаты до окончания pending replay и остаётся выключенным после него. При обновлении
обрабатываются и старый опубликованный private journal, и прежний локальный JSON journal.
Это механизм завершения замены после сбоя, а не обещание одной общей файловой транзакции Android.

CSV-импорт — отдельный незашифрованный перенос истории с preview/подтверждением. Он сохраняет
пользовательские настройки и журнал, заменяет историю, сбрасывает диагностическое состояние
и последний OK и оставляет мониторинг выключенным. Поддерживаются текущие семь колонок
UTC и старые пять. UNKNOWN rows с положительной длительностью пропускаются: формат не
отличает реальные UNKNOWN checks от generated gaps. Пробелы остаются unknown time и не
увеличивают checks. Только текущий семиколоночный CSV принимает явную zero-width
UNKNOWN-отметку без задержки (пустая ячейка или `-1`); в старом пятиколоночном формате нулевая длительность
недопустима. Отметка сохраняет текущую эпоху, даже когда в ней не осталось проверок,
и не позволяет архивным строкам стать текущей статистикой.

Наличие импорта в новой версии не добавляет экспорт в старый установленный APK. Если
старую установку нельзя обновить из-за другого signing key, удаление приложения стирает
её приватные данные; перенос возможен только из версии с доступным экспортом.
