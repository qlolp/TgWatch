# Резервная копия и перенос данных

В дополнительных настройках выберите экспорт резервной копии. Формат «Все цели — v3»
содержит публичные настройки, независимые истории Telegram, Matrix, WhatsApp и своей
HTTPS-цели, а также журнал событий. Для переноса на старую версию доступен отдельный
формат «Только Telegram — совместимый v2»: история остальных целей в него не входит.

Системный выбор документов не требует доступа ко всему хранилищу. Дважды введите
пароль **12–256 символов**. Пароль не сохраняется: восстановить забытый пароль нельзя.
Шифрование, проверка и работа с историей выполняются вне потока интерфейса.

Импорт сначала проверяет весь GCM tag и схему, затем показывает число целей/записей
и запрашивает подтверждение замены данных. Отмена, неверный пароль и неподдерживаемая
или повреждённая копия не меняют данные и работающий мониторинг. После подтверждённого
восстановления **все цели выключены**. Приватные endpoints требуют повторной проверки.

Адреса HTTPS-целей и вебхука, токены автоматизации, разрешения Android, последний
сетевой статус, последний OK и cooldowns не экспортируются. Секреты существующей
установки не заменяются секретами другого телефона. Настройки каналов Android на
новом устройстве задаются отдельно. Старые v1/v2-копии могут содержать адрес
информационной EXTRA-проверки: он импортируется отдельно в credential-protected
хранилище, не включает самостоятельную цель и не попадает в новые экспорты.

## Форматы и ограничения

| Формат | Содержимое | Ограничения и совместимость |
| --- | --- | --- |
| TGWB v3 | `TGWB`, byte `0x03`, salt16, nonce12, ciphertext и tag16; строгий JSON `formatVersion=3` | Новый экспорт всех целей; plaintext до 16 МиБ, до 98 000 наблюдений |
| TGWB v2 | Тот же 33-байтовый header с byte `0x02`; JSON v1/v2 | Telegram-only экспорт и чтение старых копий; plaintext до 8 МиБ, до 65 000 наблюдений |
| Опубликованный TGWB v1 | Header с byte `0x01`; двоичный payload TGD1 | Только чтение; прежний предел контейнера 4 МиБ |
| Локальный TGWBKUP1 | Magic8, iterations4, salt16, nonce12, ciphertext и tag16; старый JSON | Только чтение; прежний предел plaintext 8 МиБ |

Все форматы используют PBKDF2-HMAC-SHA256 (**600 000 итераций**), AES-256-GCM и случайные
salt/nonce. Header аутентифицируется как AAD. Проверка полного tag предшествует
разбору plaintext и применению. Версия контейнера и версия JSON — отдельные значения.
Старые копии открываются с исходными ограничениями длины пароля своего формата.
Неизвестные версии, лишние/обрезанные данные, дробные и переполненные числа,
неизвестные поля, дубликаты ключей и target id отклоняются.

В v3 у Telegram максимум 65 000 строк, у каждой из остальных целей — 11 000.
Глубина JSON ограничена десятью уровнями. Журнал ограничен 150 строками по 4096 символов.
Reader последовательно разбирает tuples ровно из семи элементов:
`[targetId, at, until, kind, latencyMs, clockEpoch, endpointRevision]`.
Адресов в этой схеме нет. Максимальная допустимая копия проверяется отдельным тестом
в JVM с heap 128 МиБ. Ограничения старых форматов не расширены.

**Перед downgrade создайте совместимую Telegram-only копию v2.** Старые версии приложения
не читают v3. Наличие импорта в новой версии не добавляет экспорт в старый APK.
Если обновление невозможно из-за другого signing key, удаление приложения стирает его
приватные данные: перенос возможен только из версии с доступным экспортом.

## История, прерывание восстановления и CSV

Рабочее окно истории — семь дней. Ограничение числа строк может уменьшать покрытие
при частых ручных проверках. Эпохи после перевода часов и ревизии endpoint сохраняются
раздельно. Нулевая запись `UNKNOWN`, `at=until`, `latencyMs=-1` переносит только
идентичность эпохи/endpoint: она не увеличивает checks и не создаёт покрытие.
Настоящее UNKNOWN-наблюдение положительной длительности сохраняет своё значение.

Экспорт использует один момент времени и обрезает им прогнозируемый хвост текущего
наблюдения. Восстановление применяет подтверждённые интервалы копии без изменений.
Архивные эпохи сохраняются для экспорта и не становятся текущими при истечении данных.

Каждая цель имеет собственный журнал. Новое поколение содержит registry и все журналы;
файлы и каталоги синхронизируются до атомарного переключения manifest. Исходная старая
история сохраняется после миграции и больше не подмешивается в активное поколение.
Проверки отказов и crash/reopen на каждой durable границе требуют целиком старое либо
новое поколение, без смешивания журналов. Отметка о завершённом восстановлении входит
в само поколение: потеря старого маркера миграции не возобновляет импорт прежнего источника.

Payload незавершённого восстановления хранится только в credential-protected каталоге.
В Direct Boot остаётся случайный ID транзакции. До разблокировки pending restore
не запускает проверки; после разблокировки продолжается идемпотентный replay.
Публичные настройки, журнал и истории недоступны для мониторинга до завершения replay.
При обычной ошибке применения восстанавливаются прежние данные, а validated pending
сохраняется для повторной попытки. Старые журналы мигрируют в новый приватный механизм.

CSV — отдельный незашифрованный перенос **истории Telegram**. Импорт сохраняет настройки,
журнал и истории остальных целей, сбрасывает последний статус/OK и останавливает мониторинг.
Поддерживаются текущие семь колонок UTC и старые пять. Реальные UNKNOWN rows положительной
длительности пропускаются: CSV не отличает их от сгенерированных пробелов. Текущий
семиколоночный формат принимает явную zero-width UNKNOWN-отметку без задержки;
в старом пятиколоночном формате нулевая длительность недопустима.
