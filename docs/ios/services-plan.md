# iPhone public service targets

Base e0acc83. Implement Android's Matrix and WhatsApp Web fixed public targets; no custom URLs/headers/accounts, geolocation claims, notifications for these targets, provisioning or Android edits.

- Matrix: GET https://matrix.org/_matrix/client/versions; 2xx plus complete bounded strict UTF8 JSON object, unique keys, nonempty versions array of nonblank strings <=128 UTF16 units. Reject malformed/duplicate/truncated/oversized payloads. Body64KiB, depth64/node4096 limits.
- WhatsApp Web: HEAD https://web.whatsapp.com/, GET fallback only405/501; HTTP100–499 is response evidence including auth/rate/redirect, not account/message availability. No redirect following.
- Separate selected-service monitor wraps existing lifecycle ownership; one selected target at a time, manual or60/120/300seconds while its screen is visible and app active. Selection/settings changes invalidate old results. Settings are session-only and auto checks default off. Telegram's monitor/alerts remain independent and unchanged.
- Three-second service request; failed criterion may run one three-second public control request. Completed failed criterion with control response is a failed check, not a global outage; absent control means UNKNOWN. Path unavailability is NO_NETWORK. Timeouts/transport error/HTTP error/invalid payload remain explicitly distinct evidence. No region inference.
- Typed service rows use schema2; new reader accepts legacy schema1 Telegram records. Old readers reject mixed schema2 history instead of assigning service rows to Telegram. Store bounded public evidence, never bodies/URLs. Reports/CSV/incident UI filter per target before applying session/epoch/clock rules. Service labels never say Telegram is down.
- Tests first: strict protocol parser; HTTP/code/error semantics; bounded native fixtures; selected-target cancellation/late-result rejection; foreground/hidden/stale behavior; legacy/per-target history and CSV; UI selection/check/history/Telegram isolation. Independent review then exact-head CI. Artifact403 route remains denied; use CI UI assertions/attachments without claiming visual acceptance.
